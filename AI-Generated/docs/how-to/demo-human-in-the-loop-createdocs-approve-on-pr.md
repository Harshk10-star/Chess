# Demo: Human-in-the-Loop Createdocs Approve on PR

## Overview

Goal: Approve a pull request (PR) using the human-in-the-loop Createdocs process.

This guide shows how to manually review and approve documentation changes generated or suggested by Createdocs on a PR.

## Details

### Preconditions

- You have write or maintain permissions on the repository.
- The PR includes Createdocs-generated documentation changes.
- You have access to the PR interface (e.g., GitHub, GitLab).

### Steps

1. Open the pull request in your repository hosting platform.
2. Review the Createdocs-generated documentation changes in the "Files changed" tab.
3. Verify that the documentation is accurate, complete, and aligns with project standards.
4. If changes are needed, add comments or request changes on the PR.
5. Once satisfied, approve the PR using the platform's review feature.
6. Optionally, merge the PR if you have the rights and it meets project criteria.

### Pitfalls

- Do not approve without thorough review; automated docs may contain errors.
- Ensure that all Createdocs suggestions are relevant and correctly integrated.
- Avoid merging if there are unresolved comments or requested changes.

Following these steps ensures a controlled human-in-the-loop approval process for Createdocs-generated documentation on PRs.
